From refining how property charges are calculated to building admin authentication, access controls, and audit logging, I spend a lot of time making the platform's logic more reliable.

  • Built admin password reset and email two-factor sign-in, then spent a good while making it hard to break: OTP codes that expire, attempt limits that can't be raced past, and old sessions logged out after a password reset.

  • Diagnosed and resolved intermittent production email-delivery failures affecting admin authentication and password recovery. Bugs I enjoyed fixing

the one that took the longest

bug: Admin sign-in and password-reset codes sometimes failed to arrive in production. The app still reported them as sent, leaving admins locked out without any indication of what went wrong.

digging: Every email created a new SMTP connection, and the sending process was fire-and-forget. Nothing confirmed delivery before the request reported success. Under concurrent sign-in attempts, some emails silently failed, with no useful error logs.

fix: Enabled Nodemailer's connection pooling and reused cached email providers. Made time-sensitive admin emails wait for the BullMQ worker's delivery result, with bounded retries. Rolled back issued OTPs and tokens when delivery failed, and added worker-level failure logging.

since: Several days of sustained production use without a recurrence of the delivery failures.

bug: Changing the email provider in admin settings had no effect. The long-running worker picked a provider once at startup and never checked again.

fix: Made the email service look the provider up on every send.

bug: Send enough wrong sign-in codes concurrently and you could bypass the account lockout. Each request was working with a potentially outdated attempt count.

fix: Moved attempt counting and lockout enforcement into an atomic MongoDB update.

bug: Enabling 2FA failed for admins with older profiles containing missing fields. Mongoose's full-document validation was blocking an otherwise valid update.

fix: Updated only the required OTP fields without re-validating the entire document.

bug: Concurrent settings saves could create duplicate platform settings documents instead of updating the existing one.

fix: Used a fixed document ID so every settings write targets the same record.

bug: Resetting an admin's password left previously issued authentication tokens valid. Changing the password didn't invalidate existing sessions.

fix: Added token invalidation to the password-reset flow.

bug: Some property forms sent naira amounts into fields expecting kobo. A ₦100,000 rent could end up stored as 100,000 kobo instead of 10,000,000.

fix: Corrected naira-to-kobo conversion across property creation and update flows.
